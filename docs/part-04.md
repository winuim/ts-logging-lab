# 第4回：WeakMapとunwrap

この文書は[`part-04`タグ](https://github.com/winuim/ts-logging-lab/tree/part-04)時点の設計・APIを説明します。後続回の機能は含めません。

実体→ProxyとProxy→実体の対応をWeakMapで保持し、同じ実体の再ラップとラップ済みProxyへの再適用は同じProxyを返す。`unwrap<T>(value: T): T`は登録済みProxyを実体へ戻し、それ以外のオブジェクト・関数・primitiveはそのまま返す。型の根拠は同じTの実体とProxyだけを登録する内部の対応関係であり、型アサーションは使わない。

同じ実体では最初のラップ設定が有効になる。後から別設定を渡しても再構成しない。Page/Keyboard等のラッパーを混ぜて同じ対象へ使わない。独立した設定を必要とする用途は現APIの対象外であり、複数ポリシーを管理する基盤は追加しない。

メソッドはProxy内のMapに元関数と合わせてキャッシュする。元の関数が差し替われば更新し、constructorはbindせず返す。レジストリはWeakMapだけを使い、オブジェクト一覧や逆引き用の強参照配列を持たない。メソッドキャッシュはProxyの寿命と同じで、取得したメソッドや生の実体をアプリが保持すれば、その参照先は生き続ける。GC実行タイミングやメモリ量の保証はしない。

呼び出しのトップレベル引数はunwrapして渡す。配列・入れ子のオブジェクトへ再帰せず入力を変更しない。イベントhandlerはラップせず、同じ関数をon/offへ渡すため解除できる。this戻り値をProxyへ戻すのでon(...).off(...)のチェーンも保つ。イベント引数自身をProxyへ変換する仕組みは今回作らない。

検証は単体30件と実Chrome統合7件。二重ラップ、unwrap、関数参照、元関数差し替え、Proxy引数、イベント解除、実Pageのkeyboard・gotoの安定性を確認する。既存の同期/非同期・private・失敗隔離テストも継続する。
